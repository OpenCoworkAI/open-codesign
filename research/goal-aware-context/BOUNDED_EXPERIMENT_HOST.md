# 受限本地研究执行器

日期：2026-11-01。用户已选择替代不可用的Computer Use终端输入：在已配置密钥的PowerShell启动一次执行器，由当前研究任务提交冻结批次并分析结果。研究范围仍包括基线压力实验、新增两种记忆方案、短样本验证及后续长对话／重复试验。

## 启动与限制

从仓库根目录启动，使用已有Node22和pnpm，不安装新依赖：

```powershell
pnpm exec tsx --tsconfig research/goal-aware-context/tsconfig.json research/goal-aware-context/state-experiment-host.ts --workspace .Codex/workspace/goal-aware-context/goal-20261101/experiment-host-001 --config .Codex/workspace/goal-aware-context/goal-20261101/stress.local.json --max-calls 300
```

启动后没有任务就等待，不调用模型。现有密钥只通过进程环境交给同一研究CLI，状态文件只写凭据是否存在的布尔值。配置文件不保存密钥，日志对已知凭据回显进行脱敏。

- 初始总上限300次，逐批预留配置中的maxCalls，不能通过任务文件增加上限。失败批次也不自动退回预留额度；这是保守执行额度，不是供应商账单计数。
- 每批仍需明确的配置、来源指纹匹配的plan.json和新输出目录。固定现有模型、地址、凭据环境变量、窗口声明、4096输出、1800字节摘要及60秒超时；不自动重试或重复运行同一计划。
- 只接受任务标识、track、配置路径、预演路径和输出路径。所有路径限定在启动目录的父研究目录中，并检查真实路径／符号链接；拒绝既有输出目录和任意命令字段。
- 只启动固定的state-stress-cli.ts，shell=false。每批一个全新的Node进程，直接导入tsx，避免后续研究实现更新时误用缓存模块；报告executorPid必须等于所监控的子进程PID。
- 配置和预演会复制到任务快照目录，再启动；提交后的源配置修改不会改变在途任务。子CLI仍会验证完整预演、源码、任务及参考指纹，再访问凭据和模型。
- 执行器及其策略源码在运行期间保持冻结；若它们改变则拒绝新任务。后续新方法修改研究CLI后，须生成新预演，不能重用旧计划。
- 不开放网络监听端口，不执行任务提供的脚本，不修改产品或系统设置。它是受限研究调度器，不是OS沙箱；实际模型调用上限由现有统一调用边界共同执行。

最多运行4小时，连续空闲1小时自动停止。Ctrl+C或研究控制目录下的STOP文件请求停止；持久化故障会先取消活动任务。强制终止可能留下不完整调用记录，不能据此声称实际调用数为0或任务完成。

## 任务与证据

目录不存在时才可启动，防止无意复用旧队列／额度。目录结构：

- host.json：父PID、时间、心跳、状态、活动子PID、总预留额度、模型元数据与凭据就绪布尔值。
- requests/*.json：由当前研究任务原子提交的新批次；不是任意Shell命令。
- jobs/<id>/：接受时的配置和预演快照。
- ledger.jsonl：开始执行前持久化的额度预留；同一计划不能自动重放。
- results/<id>.json：running、completed、incomplete、interrupted、failed或rejected；最终实际调用数仅从身份／指纹一致的CLI报告读取，未知为null。
- logs/：子进程安全的标准输出／错误。详细模型请求、响应及评分仍保存在该批次原输出目录。

读取host.json并不足以证明任务仍在运行。提交与等待时还需核对具体父／子PID是否存在、心跳是否更新；观察超时后应核对原任务，不能重新启动批次。

队列文件应先写完整临时文件，再原子改名为`<id>.json`。任务示意：

```json
{"id":"reader-v2-001","track":"calibration","config":"研究根内的绝对配置路径","preflight":"研究根内的绝对plan.json路径","output":"研究根内的新输出目录"}
```

首批先运行12次完整前缀读取校准，分析后再运行64次基线压力实验。随后才实现并评测goal-recall与stable-handoff，最后扩展长对话与重复试验。新方案未实现前，执行器不会自行调用它们。
