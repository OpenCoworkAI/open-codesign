# 研究扩展：目标召回、可追溯状态与连续压缩

日期：2026-10-28。状态：**已纳入当前分支研究路线图，尚未实现或验证**。

本文件是可行性与实验范围建议，不是可直接执行的实现规格。提出的默认选择属于本次研究建议，尚不代表用户确认了具体预算、标注或调用计划。后续实现需要独立的版本化协议、任务计划和零调用预演。

## 为什么加入这三项

development-live-003 已显示两个具体问题：目标记录摘要漏掉“先重读 App.jsx 再重试预览”；摘要将未批准的外部 r2 修改误当成已失效，从而把用户批准色和旧版本答成当前磁盘事实。当前严格评分还存在同义/中英文误扣，待复核条目不能自动改分。

三项扩展分别回答：应该带哪些上下文；带入的状态是否正确、可追溯；连续更新之后是否仍可靠。它们沿用现有研究基础，不需要新建分支或接入外部记忆产品。

现有基础包括生产适配器、冻结语料与预算检查、统一运行与调用记录、内容/格式/综合评分、宿主事实对照，以及 goal-state.ts 和 candidate-pack.ts 的来源/版本/替代关系检查。后两者目前消费特权标注，是草稿 oracle；不能作为模型已经能正确抽取状态的证据。

## 1. 新增上下文方案

### 按目标召回：goal-recall（拟议条件）

保留不可变原始轨迹，以截止点已知的当前目标召回相关事件，再按完整请求预算组合证据。先做无外部依赖的事件切分、目标词与对象/文件匹配、去重和确定性排序；向量检索和分层召回留作后续消融，不在首版同时增加。

目标应来自截止点已公开的任务输入，或统一记录的目标提取阶段。所有比较方法获得相同的目标信息，提取调用及索引构建也计入开销。目前统一入口给压缩器的目标是泛化的“恢复当前设计”，不能用评测答案反向补成更具体的目标。

召回不能只找相似旧决定：还要带上影响被选事实的最新更正、撤销、冲突和版本更新。记录候选事件、选中来源、被排除原因、去重率与证据覆盖率。覆盖率金标只交给评测器，不参与选择。

在同一案例中，召回结果先冻结，再回答所有问题；禁止用每道评测问题、参考答案或未来 nextEditRequest 作为查询。若研究“已知新的用户请求之后才整理记忆”，另开任务已知的实验组，并把同一请求提供给全部方法。

依据：[Just-in-Time Memory](https://arxiv.org/abs/2609.27334) 将整理延迟到当前任务已知时；[xMemory](https://arxiv.org/abs/2602.02007) 强调拆分重复内容、组合互补证据。这是借鉴机制的独立研究条件，不声称复现论文的训练或完整系统。

### 稳定约束＋短期交接：stable-handoff（拟议条件）

将一份上下文分成两部分：

- 稳定约束：仍有效的用户决策、禁止事项、保护对象及其适用范围。稳定不等于全局或永久；新批准决定仍可替代旧决定。
- 短期交接：当前目标、实际文件版本、最后有效观测、失败/未完成工作、必须先执行的下一动作和待澄清差异。

两部分共享总预算。建议首轮沿用2K完整请求上限和合计1800字节的派生记忆额度，不能分别各给1800字节；分配规则在小批量运行前冻结。每轮只更新受新增事件影响的状态，同时保留撤销与冲突记录。

例如，批准色仍为蓝色、磁盘 r2 实际为绿色，应同时保留并标为未解决差异；“未批准”不会让磁盘回退。“先重读文件”应作为必要动作保存，不能被“继续验证”概括掉。

依据：[PowerContext](https://github.com/oceanbase/powercontext) 区分可持续的 Memory 与工作接续的 Handoff。这里仅研究这种分工，不引入其服务器、自动纠偏 Agent 或产品持久化系统。

## 2. 可追溯状态评测

新增独立的状态评测组，保留现有问答、格式、运行有效性与宿主事实组。建议以“设计/文件/对象/字段＋状态种类”标识一个状态项，分别记录四项分数，并报告四项同时正确的比例：

| 维度 | 检查什么 | 失败示例 |
|---|---|---|
| 当前值 | 该种类状态在截止点的值是什么 | 把批准的蓝色答成磁盘实际绿色，或反过来 |
| 作用域 | 属于哪个设计、文件、对象和字段，是否允许继承 | 把旧营销页的紫色带到明确改用白底黑字的 onboarding |
| 来源 | 来源事件、角色、工具结果与版本是否确实支持该状态 | 用助手建议当批准，引用未来事件，来源编号存在但不支持结论 |
| 失效条件 | 什么事件会使它不再是当前有效结论 | 文件已到 r2，仍沿用 r1 的预览成功 |

“当前值”必须区分用户意图、磁盘观测、验证结论和待办义务。失效也应按种类判断：用户决定由新批准/撤销等改变；文件观测由新读取更新；预览只对其绑定版本有效。旧观测仍可作为历史证据保留，但不能冒充当前验证。设计切换不会自动撤销明确的全局限制。

模型抽取结果与 oracle 标注分开报告。模型输出的来源引用、作用域和生命周期由确定性检查验证；引用语义是否成立仍需要证据标注及人工裁决，不能只检查编号存在。来源缺失、未决冲突和未知状态要显式保留。

为比较不同表达形式，使用相同的状态读取任务，读取各方法已经冻结的上下文；不向读取模型开放原始档案来补齐丢失证据。结构化候选可另做直接字段审计，但不能和自由文本读取成绩混称为一种测量。新增读取调用和模板需要单独计数与版本化。

依据：[Nemos Memory](https://github.com/mmlong818/nemos-memory) 将原始输入、派生事实、来源与事实变化分开维护。本项目只借鉴数据语义并独立实现；其当前非商业许可不适合直接复制代码或引入 SDK，本项目也不采用其 SQLite 存储路径。

## 3. 压力测试

| 测试 | 首批建议 | 必须有的对照与指标 |
|---|---|---|
| 连续压缩 | 在相同最终事件前缀上比较0/1/3/5次压缩；逐轮加入更正、文件改动和目标切换 | 0次为完整历史参考；1次为最终前缀的一次压缩；多次更新只读上一份记忆＋新增事件。记录首次关键状态丢失轮次、旧约束复活、必要动作遗失及最终状态四维成绩 |
| 纠错迁移 | 同一源经验的纠正前、纠正后，分别迁移到固定目标任务 | 同时比较不继承旧经验的独立起步；既测应保留的修正，也测不应泛化的局部约定。不能只看纠正前后差值 |
| 跨设计错误继承 | 切换设计，分别设置明确局部约束、明确全局约束和适用性未决的成对案例 | 局部配色不得乱带，全局约束应继续保留，未决项应澄清。记录错误继承率与正确继承率，防止“全部忘记”反而得高分 |

依据：[After the Fix](https://arxiv.org/abs/2609.34603) 区分纠正经验的收益与复用经验的收益，并要求独立起步参照；[Mosaic](https://arxiv.org/abs/2610.22174) 研究跨会话轨迹与训练。0/1/3/5次压力测试是本分支的实验设计，不是上述论文已经在本项目上验证的设置；不引入强化学习训练。

公平性边界：连续交接的封闭轨只允许旧记忆＋增量；允许回源的召回轨可访问历史档案，需要单独标识档案访问、检索与构建成本。两轨可比较任务效用，但不能把回源后的正确结果解释为摘要本身未丢信息。各轮评测问题和答案不得回流进下一轮记忆；只有轨迹中明确的用户纠正事件可成为新输入。

复用 R2/R3/R5 等案例构建开发轨迹，但 R5 的跨文件适用性仍未决，不能补成已确认继承规则。新增正反例应明确授权边界，按连接的源/目标设计家族划分开发/保留集，预先冻结时间线、压缩点和参考状态；不改写旧语料及历史运行。

首次压力测试以状态与受控动作回放为主。真实任务完成率还需要文件差异、工具回执及当前版本验证；不能由问答全对或宿主模拟直接推定。

## 建议实施顺序与验收门槛

1. **先补可追溯状态评测和小型压力材料。** 优先覆盖 r2/实际颜色、重读文件义务和跨设计作用域。继续处理 development-live-003 的待复核答案，保留原成绩及裁决版本。
2. **再加入两种上下文条件。** 与普通摘要、原目标记录和等预算生产基线比较；原目标记录保留为对照，新方法必须另取条件标识。所有方法共享截止点、目标信息、读取模型和总输入限制。
3. **先做2K、单模型的小批量，再扩展连续压缩。** 当前 Doubao-Seed-2.0-mini 继续作为首个模型。先验证计数、故障保留、证据隔离和关键失败案例，再扩展轮次、预算与第二个模型。
4. **据证据决定是否继续。** 必须分别观察正确状态保留、作用域误继承、失效处理及实际开销；不预设任何新方法获胜。

新增状态任务、压缩轮次、检索或提取阶段都会改变调用量，因此不能沿用169次上限。实现计划必须按新矩阵生成独立的零调用预演，再提供具体付费运行说明。此处没有授权或发起新的模型 API 调用。

## 接入边界

- 新方法接入研究计划/运行器；沿用统一模型调用、指纹、预算、日志与失败分母。实际扩展前先固化方法选择和状态评测接口，再写实现计划。
- 新状态协议、压力语料与评分文件单独版本化，旧问答与宿主事实成绩不混算。保留集不用于修正提示词或补答案。
- 原始轨迹和实验文件使用本地 JSON/JSONL；保持 pi 的产品会话和现有存储边界。不修改生产 compaction、权限、桌面 UI，不引入外部 SDK、数据库或模型审查者。
- 本文件及 README/路线图的文档更新不改变执行指纹；以后修改研究代码或评分规则时，须重新生成预演计划。
